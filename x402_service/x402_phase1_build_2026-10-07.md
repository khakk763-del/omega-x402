   server verify → facilitator correctly re-challenged (still 402) **because the
   payer holds 0 testnet USDC**. Middleware, signing shape, and facilitator

## Public hosting outcome (2026-10-07, fallback run — Cloudflare signup NOT retried)

**Result: the service is PUBLIC and answering correct 402 challenges.**
Current URL (rotates on tunnel restart; always in `current_public_url.txt`):
`https://f279a9a7cef551f0-87-81-243-79.serveousercontent.com`

Verified from the public URL (via the egress proxy, i.e. off-localhost):
- `GET /health` → 200 `{"status":"OK","network":"eip155:8453","payTo":"0xCF33…1bD2"}`
- `GET /v1/money-flow/latest` → **HTTP 402** with `Payment-Required` header;
  decoded accepts: scheme `exact`, network `eip155:8453`, Base USDC asset,
  amount 20000, payTo burner, Bazaar extension present, and the
  resource URL inside the challenge is the public Serveo URL itself.
- `POST /v1/x402/readiness` → **HTTP 402** (same shape).

**How it is exposed — Serveo SSH tunnel through the HTTP proxy.**
Root causes found and worked around:
1. This VM's local DNS stub maps every external name to 198.18.0.0/15
   fakes and cannot answer SRV, so cloudflared edge discovery dies
   (`lookup _v2-origintunneld._tcp.argotunnel.com: server misbehaving`).
   Creating the quick tunnel via the HTTP API through the proxy works,
   but the connector still cannot reach the edge.
2. Raw outbound TCP/QUIC from this environment is intercepted (a TLS
   handshake to a real Cloudflare edge IP returns a plaintext policy
   banner instead of TLS), so cloudflared (TCP/QUIC :7844), bore, and
   any raw-socket tunnel (localtunnel's data sockets included) cannot
   connect. Only HTTP(S) through `hatch-egress-proxy:3128` works.
3. SSH **can** ride the proxy: `ProxyCommand="nc -X connect -x
   hatch-egress-proxy:3128 %h %p"` to port 443. Serveo accepts SSH on
   443 and has no session expiry while connected (Pinggy works too but
   unauthenticated sessions die at 60 minutes — tested, then retired).

**Resilience:** `tunnel_watchdog.sh` (started by `run_stack.sh`, which now
launches the watchdog instead of the dead cloudflared path) keeps the
ssh tunnel alive, rewrites `current_public_url.txt` on every restart,
and public-health-checks it every 60s. Live processes at verification:
uvicorn (8766), watchdog, ssh/serveo — all up. **Caveat:** the subdomain
changes whenever the tunnel restarts, so this is a working public
endpoint, not yet a stable listable URL.

(a) Listing an hourly-rotating subdomain would register a dead URL;
